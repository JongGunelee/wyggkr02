## 1. 개요 및 배경

사용자가 보고한 스크린샷(`D:\02 기숙사 및 사택\...\__BACKUP_보존용__\fxfile_run_x64_Backup(레거시 64bit 빌드) - fxfile (응답 없음)`) 증거를 기반으로, 대용량 레거시 바이너리 및 다수 DLL이 포함된 폴더 진입 시 발생하는 **UI 스레드 블로킹(무응답/프리징) 결함을 근본적으로 해결**하기 위한 무결성 보증 리팩토링 계획입니다.

## 2. 4대 근본 원인과 무결성 보증 해결 계획 (1:1 대응)

### [원인 1] `getFileType`의 UI 스레드 동기 `SHGetFileInfo(SHGFI_TYPENAME)` 호출 블로킹
* **현상 및 위치**: 
  - `src/fxfile/explorer_ctrl.cpp` (`getFileType`, 줄 1613~1640)
  - 폴더 진입 및 리스트 항목 생성 시, 각 파일의 종류 텍스트를 얻기 위해 메인 UI 스레드에서 `::SHGetFileInfo(..., SHGFI_PIDL | SHGFI_TYPENAME)`를 직접 동기 호출.
  - 대용량 실행 파일(`fxfile_stable.exe` - 7.6MB)이나 서명 없는 구버전 DLL이 있을 때, 백신(Defender/V3)의 실시간 파일 스캔이 개입하면 API 반환이 수 초간 지연되어 UI 메시지 루프가 정지됨.
* **무결성 보증 리팩토링**:
  1. **확장자 기반 고속 정적 1차 캐시 (Fast-Path Cache)**:
     - 시스템 공통 확장자(`.exe`, `.dll`, `.zip`, `.txt`, `.ini`, `.conf`, `.dat`, `.xml` 등 30여 종)에 대한 유형명을 사전에 매핑하여 0ms 즉시 반환.
  2. **레지스트리(`HKCR`) 프로세스 메모리 캐시 (Process-Level Memory Cache)**:
     - 한 번 조회된 파일 확장자의 유형명을 `std::map<xpr::string, xpr::string>`에 캐시하여 동일 확장자 반복 조회 시 Shell API 호출을 100% 제거.
  3. **UI 스레드 완전 격리**:
     - 알 수 없는 특수 항목의 경우에만 최소한의 안전 Fallback을 사용하고, 동기 블로킹 유발 지점을 원천 차단.

### [원인 2] `ShellIcon` 및 `Overlay` 비동기 워커의 STA COM RPC 경합 및 재진입
* **현상 및 위치**:
  - `src/fxfile/explorer_ctrl.cpp` (`OnGetdispinfoShellItem`, 줄 1053~1186)
  - `src/fxfile/shell_icon.cpp`
  - 리스트뷰 렌더링 시 다수의 실행파일/DLL에 대해 아이콘(`sAsyncIcon`)과 오버레이(`TypeOverlayIndex`) 요청이 동시에 발행되어 워커 스레드와 UI 스레드 간 COM(STA) 메시지 마샬링 경합 발생.
* **무결성 보증 리팩토링**:
  1. **확장자 시스템 기본 아이콘 즉시 반환**:
     - `.exe` 및 `.dll`에 대해 시스템 기본 아이콘 인덱스(`GetFileExtIconIndex`)를 0ms 즉시 채택하여 화면에 먼저 표시.
  2. **워커 큐 중복 방지 및 원자성 보장**:
     - `mIconRequestIssued`, `mOverlayRequestIssued` 플래그의 완전한 상태 머신을 구축하여 동일 항목에 대한 큐 누적 및 무한 피드백 루프를 차단.
  3. **COM 안전 호출 및 타임아웃 가드**:
     - `ShellIcon` 워커에서 `IExtractIcon` 호출 시 오류 및 지연 발생 시 즉시 기본 아이콘으로 안전 롤백.

# Task128 — 창 크기 모드와 재시작 복원

두 체크는 항상 같은 값을 갖는 체크가 아니라 서로 다른 모드를 선택한다.

| 자동 창 크기 맞춤 | 창 분할·크기 잠금 | 동작 |
|---|---|---|
| ON | OFF | 명시 새로 고침/전체 창 크기/레이아웃 변경 시 동일 크기로 맞춤 |
| OFF | ON | 잠금 선택 때 저장한 분할 배치를 다음 실행에 복원 |
| OFF | OFF | 마지막 수동 조정 크기를 정상 종료·재실행 후 유지 |

- 자동 맞춤을 켜거나 해제하는 명시 명령은 분할 잠금을 해제한다. 분할 잠금을 켜는 명령은 자동 맞춤을 해제한다. 메뉴의 체크 표시도 실제 옵션값에서 읽는다.
- 마지막 수동 크기를 유지하려면 두 체크가 모두 꺼져 있는지 확인한 뒤 분할선을 조정하고 정상 종료한다. 분할 잠금만 ON인 상태라면 그 잠금을 해제하면 수동 모드가 된다.
- 기존 설정에서 둘 다 ON이면 시작 시 분할 잠금 스냅샷을 우선 보호하며 자동 맞춤을 OFF로 정규화한다. 기존 잠금 저장값과 위치·경로·시계 잠금은 변경하지 않는다.
- 창 > 같은 비율로 분할하기는 모드에 관계없이 일회성 명령이다. 두 체크 OFF일 때 이 명령으로 맞춘 크기도 새로운 마지막 수동 상태가 된다.
- 환경 설정의 비율 유지/고정 픽셀 유지 동작은 그대로다. 다른 해상도/창 크기에서는 그 설정과 최소 패널 크기 경계에 따라 화면 크기가 달라질 수 있다. 강제 종료/충돌의 저장을 보장하지 않는다.

2026-10-14 최종 검증 완료. x32 고정 픽셀(425/295/326)과 x64 비율(0.424354/0.239852/0.627097)에서 두 체크 OFF 상태의 F5 명령·정상 종료·재실행 후 여섯 pane의 실제 HWND 위치/크기와 저장값이 모두 동일했다. F5는 실제 가속기가 라우팅하는 `ID_VIEW_REFRESH`(33040) 명령으로 실행했다. 화면은 각 앱 HWND를 `PrintWindow`로 캡처하고 직접 확인했다.

운영본의 자동 맞춤 OFF·분할 잠금 ON과 사용자 폴더 배치를 보존해 세 패키지 설정 10개를 재동기화했다. 최종 성공 manifest는 `__BUILD_TEMP_BACKUP__/unified_deploy_20261014_061838_941/deployment_manifest.json`이다. 정적 회귀 46개·신규 13개, x64/x32 6/6 pane 준비·정상 종료를 통과했다. 상세 정리 결과와 최종 VerifyOnly는 가이드 Task128 및 `__BUILD_TEMP_BACKUP__/task128_results_20261013/RESULTS.md`를 따른다.

## 빌드 PDB 오류의 별도 복구

기존 runtime-root `fxfile.pdb` 쓰기 LNK1201 및 이동 거부를 관측했다. 소유권/다른 프로세스 핸들/보안 설정은 변경하지 않는다. 링크 PDB만 각 아키텍처의 빌드 캐시 `src/fxfile/link_symbols/<Config>`로 분리하며 `/DEBUG` 생성은 유지한다. 이 설정은 [CMake PDB_OUTPUT_DIRECTORY 공식 계약](https://cmake.org/cmake/help/latest/prop_tgt/PDB_OUTPUT_DIRECTORY.html)을 따른다. 컴파일러 PDB(`/Fd`)와 링크 PDB(`/pdb`)를 혼동하지 않는다.
